<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| re-dispatched workflow step -> Transfer | The same step_key arrives again (F5, retry, restart) |
| restarted tool server -> core ownership | The core may not own a guid the ledger recorded (core limit 1) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-22 | Tampering (integrity) | replay | high | mitigate | Replay only for done+ran inside 600 s with a matching fingerprint. The endpoint is in the fingerprint, so another STACK is a mismatch (tested) |
| T-05-23 | Elevation of privilege (safety) | restart mid-transfer | high | mitigate | The re-attach is read-only. A non-ran result after a restart carries the arm-inspection clause plus the live latch guid. A submitting record after a restart is refused (tested) |
| T-05-24 | Denial of service | re-attach loop | medium | mitigate | Bounded by the budget T (clamped at 3600), 300 s slices, exits on any non-timedOut result, never calls with remaining <= 0 (tested) |
| T-05-25 | Tampering | step-key normalisation | low | accept | The key is byte-exact by design. A re-dispatch repeats the identical string, and a variant is a different key (documented and tested) |
| T-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | No install. The core pin is unchanged |
</threat_model>
