## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| galago-core (protocol or tool page) -> AcknowledgeFailure | galago-core cannot hide the command from protocols, so the yes-gate and the core's exact-guid match are the guard |
| core latch state -> operator message | The guid the operator types back must be the one the core will accept |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-05-13 | Elevation of privilege | AcknowledgeFailure | high | mitigate | Exact "yes" (byte equality, 11 negative variants tested). Checked in _dispatchCommand and again in the handler. Core confirm=True plus exact guid plus recovery read. Single call site (AST). Ack never edits the ledger |
| T-05-14 | Repudiation / safety | operator guid in messages | medium | mitigate | The guid comes from latch_status() first (A-2). The task guid is labelled separately. The first-failure-wins case is tested |
| T-05-15 | Information disclosure | message truncation / core text | low | mitigate | The reason is capped at 60 characters so the guid survives the 300 cap (tested). explanation is never read (Phase 4 D-11) |
| T-05-16 | Denial of service | latch_status failure inside an error reply | low | mitigate | `_latch_clause` never raises, and falls back to "read GetFailureLatch" |
| T-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | No install. The core pin is unchanged |
